# 9. Boards are grouped into collections, imported from JSON, and managed in the app

Date: 2026-11-25

## Status

Accepted. Partly supersedes ADR 6: boards are no longer defined only through
seeds. Implemented: collections and JSON import (PR #10), managing
collections and boards (PR #11), the board editor (PR #12), and the import
page (PR #13).

## Context

ADR 6 put board writing in `priv/repo/seeds.exs` until an editing screen was
needed. Two things have changed:

- Boards are now generated by another agent from lessons, so there needs to
  be a file format it can write and a way to load those files, including in
  a deployed app where `mix` is not available.
- There are enough boards to need a level above them: "Primary Lessons",
  "General Knowledge", and so on. "Category" already means a column on a
  board, so this level needs another name.

## Decision

**Collections.** Every board belongs to exactly one collection (`collections`:
`name`, unique). Board names are unique within their collection, not across
the app, so "Lesson 1" can exist in more than one collection. A board that is
created or imported without a collection goes into one named "General". The
setup page lists boards under their collection.

**JSON import.** A board is written as JSON in the format documented in
`docs/board-format.md`: a collection name, a board name, and nested
categories and clues, positioned in the order they are listed. A file holds
one board or a list of boards. `Cluebert.Boards.Import` validates a whole
file and imports it in one transaction: either every board in it is
imported, or none is, with errors that name the board, category and clue at
fault. A board whose name already exists in its collection is rejected
unless the import is told to replace it. Entry points:

- `mix cluebert.import FILE... [--replace]` for development.
- `priv/repo/seeds.exs`, which imports every file in `priv/boards/` and
  replaces boards of the same name.
- An upload page in the board management UI, for the deployed app.

**Board management UI.** Collections, boards, categories and clues can be
created, edited, reordered and deleted in the app, on the schema from ADR 6
plus collections.

ADR 6's schema and any-shape boards stand. ADR 5 still applies: imports and
edits never affect a game in progress.

## Consequences

- Generated content can be loaded without code changes or redeploys.
- The board format is a contract with whatever generates boards. Changing
  it means updating `docs/board-format.md` and keeping old files importable
  where practical.
- Replacing a board deletes it and creates a new one, so its id changes.
  Running games are unaffected (ADR 5). Nothing else stores board ids yet.
- The management UI has no access control, for now (ADR 10).
